# confidential-sanitizer

外部AIにテキストを貼り付ける前に、組織名・氏名・識別番号などを確認し、`<ORG_01>` のような文字列へマスキングするツールです。**テキストの確認と置換はブラウザ内で完結します。安全を保証する製品ではありません。**

## 使い方

画面は3カラム構成です。左で入力とハイライトを切り替え、中央で検出候補・置換先を確認し、右でマスキング結果をコピー・保存します。ページ全体を縦スクロールせず、長文と候補一覧だけを枠内でスクロールします。PCの横幅1100px以上を想定し、狭い画面では作業領域内を横スクロールできます。

右上の「？ 使い方」で説明を開けます。「閉じる」、説明の外側のクリック、Escキーで閉じられます。「マスキングする種別」のメニューも外側のクリック・Escキー・外へのフォーカス移動で閉じられます。

左上の「入力をクリア」で入力・候補・出力・手動選択を消去し、処理中のAIを停止します。種別の設定は維持します。チェック後も「入力・編集」で入力に戻れます。

1. テキストを入力し「チェックを実行」を押します。メール、電話、IP、URL、郵便番号、住所の一部、番号、ホスト名などをルールで探し、続けてブラウザ内AIで名前・組織名などを確認します。入力欄の近くの「マスキングする種別」を開くと、対象を絞れます。初期状態ではすべて選択されています。チェックを外した種別の候補は残りますが、マスキングされません。
2. AIはチェック実行時に読み込みます。起動時やテキストを貼り付けただけでは読み込みません。初回は**このアプリと同じサイトから**約279MBの日本語モデルを取得し、氏名、企業・団体・組織、地名、施設、製品、イベント等を確認します。進捗は実行ボタンの近くに表示します。モデルがない場合や解析に失敗した場合も、形式で検出した候補は残り、AIチェック未完了と表示します。
3. 検出箇所は色付きで表示されます。候補は同じ文字列をまとめ、列名付きの表に表示します。検出方法・AIの信頼度は元の文字列の下に表示します。チェックを外すとその行の箇所をマスキングしません。箇所数と合計も表に表示します。見落としたシステム名や案件名は、**検出結果に表示されたテキストでその文字列を選択**し、「＋ 手動追加」を押します。種別の選択は不要です。手動追加分は「その他」に分類し、必要なら後から表で種別や置換先を変更できます。画面の種別名は日本語表示です（例：ORG＝企業・団体、PERSON＝氏名）。置換後のテキストでは `<ORG_01>` などの記号をそのまま使います。
4. 候補の表にある「一覧をコピー」は、実際にマスキングする元の文字列と置換先を表計算ソフトへ貼り付けやすい形式でコピーします。「CSVで保存」はCSV（表を保存するテキスト形式）をダウンロードします。コピーとCSVの種別は、置換後の `<ORG_01>` と対応する `ORG` などのコードで出力します。**元の機密情報を含む**ため、コピー先や保存先に注意してください。
5. マスキング後のテキストを**全文目視確認**してから「コピー」または「TXTで保存」を押してください。TXT（文字だけのファイル）をPCへダウンロードできます。外部AIへ自動送信する機能はありません。

同じ種別・同じ文字列は同じ番号を使います。たとえば同じ会社名が２回出ても両方 `<ORG_01>` です。重なった候補は手動→ルール→NER、同じ方法なら長い候補を優先して置換します。テキストを変えずに再チェックした場合は、候補の解除・種別・置換先の編集を保持します。テキストを編集・消去すると処理中のAIチェックを中断し、古い結果は表示しません。

## ソースから開発する

以下はソース一式を取得した開発者向けの手順です。npmパッケージをインストールした利用者は [起動方法](docs/npm-package.md) を参照してください。Node.js 22.12以上とnpmを用意し、次を実行します。`npm run dev` / `npm run build` 時にブラウザ用のWASMファイルを `public/wasm/` にコピーします。モデル本体はインストール・Git保存されません。開発中もブラウザはHugging Faceへ接続しません。NERを試すには、CIで取得済みのモデル一式を `public/models/` に配置する必要があります。

```bash
npm install
npm run dev
npm test
npm run build
```

WindowsでGitHubからソース一式をZIPでダウンロードした場合は、ZIPをすべて展開して、`package.json` と `package-lock.json` があるフォルダの `preview.bat` をダブルクリックしても起動できます。初回は依存パッケージをインストールし、ブラウザを開きます。ソースZIPにはAIモデルが入らないため、ここでは形式が決まった情報のチェックを試せます。

AIを試す場合は、CIで取得済みの `models` フォルダをソースの `public` フォルダへ配置します。`public/models/jiting/xlm-roberta-ner-japanese_onnx/config.json` 等がある状態にしてください。一度取得したモデルは再利用できます。npm版のモデル配置は [利用方法](docs/npm-package.md) を参照してください。

開発URLはターミナルに表示されます。配布するファイルは `dist/` 内です。Viteは開発・ビルド用の道具で、完成したページにはサーバー処理がありません。`.npmrc` はPCでは使わないONNX RuntimeのCUDAダウンロードを省く設定です。

## 仕組みと通信

| 用語 | 短い説明 | このツールでの役割 |
| --- | --- | --- |
| NER | 文章中の名前や組織などを見つける方法 | 番号や記号の形式だけでは見つけにくい固有名詞を候補にします |
| ONNX | 学習済みモデルを動かすための共通形式 | 日本語NERモデルの配布形式です |
| WASM | ブラウザで計算用プログラムを動かす形式 | モデルの計算をPCのブラウザ内で実行します |
| tokenizer | 文章をモデルが扱える小さな単位に区切る部品 | モデルと一緒に取得します |

- ルールによる検出処理：**外部通信なし**。入力テキストはLocalStorage、IndexedDB、Cookie、アクセス解析、ログへ保存しません。ページ再読込時に内容は消えます。
- 「チェックを実行」でAIを使うとき：ブラウザは**アプリと同じサイト**からモデル、tokenizer、WASMを取得します。Hugging Faceからの取得はCIでだけ行います。**入力テキストは配信サーバーにも推論APIにも送信しません**。ブラウザや配信サーバーによる通常のアクセスログには、静的ファイルのURLやIPアドレスが残る場合があります。
- このツールはモデルキャッシュを無効にしています。ページ再表示時には同じサイトからモデルを再取得する可能性がありますが、**CIをチェックのたびに実行する必要はありません**。入力テキストはブラウザ内メモリにのみ保持します。コピー後のクリップボード、明示的にダウンロードしたファイルの扱いは利用者のPCの設定に依存します。
- CIのみモデル提供元へ通信します。利用者のPCはHugging Faceへ接続しません。入力テキストはHTTPリクエストに含めません。
- 外部フォント・解析タグ・外部AI APIは使いません。CSP（読み込み先を制限するブラウザ設定）の通信先を同じサイトだけに限定しています。配布先のHTTPヘッダーでも設定することを推奨します。WASMの実行には `script-src` の `'wasm-unsafe-eval'` が必要です。これはWASMの計算を許可する設定で、JavaScript文字列の実行を許す `'unsafe-eval'` は追加しません。Worker（画面と別に計算する仕組み）の配信応答へCSPを付ける場合も同じ点を確認してください。

## 使用モデルと限界

[jiting/xlm-roberta-ner-japanese_onnx](https://huggingface.co/jiting/xlm-roberta-ner-japanese_onnx)（元モデル：[tsmatz/xlm-roberta-ner-japanese](https://huggingface.co/tsmatz/xlm-roberta-ner-japanese)）。Hugging FaceのモデルカードはMITライセンスを表示しています。量子化した `onnx/model_quantized.onnx` は約279MBです。モデル全体の保管容量は約1.97GBですが、このアプリは量子化版を要求します。tokenizerは約17.1MBで、別途設定ファイルを取得します。速度と精度はPC性能や文章で変わります。

このモデルはWikipedia由来の学習データを使っています。独自の名称、略称、案件名、システム名、未学習の人名、表記揺れは見落とす可能性があります。施設と場所、企業名と製品名なども誤って分類することがあります。NER結果の文字位置はモデルAPIに含まれないため、単語を元文章に順に照合して位置を推定します。照合できない単語は採用しません。長文は約400文字ずつ処理するため、分割位置をまたぐ名称も見落とす場合があります。**このツールだけで外部共有の安全は保証できません。**

## 静的サイトとして配布する

特定のホスティングサービスに依存せず、HTML・JavaScript等を配信できるWebサーバーへ配置できます。npmパッケージからは `confidential-sanitizer export ./site`、ソースからは `npm run build` で配布用ファイルを作成します。npm版の詳しい操作は [利用方法](docs/npm-package.md) を参照してください。

AIを使う場合は、別配布のモデル一式を公開フォルダの `models/` に配置します。モデル、tokenizer、WASMをアプリと同じサイトから読み込める状態にしてください。利用者のブラウザでは `env.allowRemoteModels = false` として、外部のモデル配布元への接続を無効にしています。

ソースに含まれる `scripts/fetch-model.mjs` はCI（テストや配布物作成を自動実行する環境）でのみ実行でき、固定版のモデルを取得・照合します。取得元を変更する場合はCI変数 `MODEL_BASE_URL`、認証が必要な場合は `MODEL_AUTH_TOKEN` を設定します。モデルのファイル構成とハッシュ（改変を検出するための値）を維持すれば、アプリの変更は不要です。

配布先の容量上限・アクセス制御・キャッシュ設定を確認してください。配布するモデルは、そのサイトの閲覧者がダウンロードできる状態になります。相対パス配信に対応しており、favicon（ブラウザのタブのアイコン）も同じサイトから読み込みます。

ソース管理者向けの具体的な設定は [配布基盤ごとの設定例](https://github.com/smjr3/confidential-sanitizer/blob/main/docs/deployment.md) を参照してください。

## 構成とライセンス

`src/detection/regex`（ルール）、`validators`（番号検証）、`ner`（NER結果の位置と分類）、`manual`（手動追加）、`src/anonymize`（重なりと置換）、`src/model`（モデルとWeb Worker）、`src/security`（入力上限）、`src/ui`（画面）、`tests`（単体テスト）。独自の社員番号・管理番号のルールは `src/detection/regex/index.ts` の `extraRules` 引数から追加できます。機密情報を含む値をルールに直接書き込むと、配布するソースから読み取られるため注意してください。

| npmパッケージ | 用途 | ライセンス |
| --- | --- | --- |
| `@huggingface/transformers` | ブラウザ内のNER | Apache-2.0 |
| `typescript` | 型検査 | Apache-2.0 |
| `vite` | 開発・ビルド | MIT |
| `vitest` | テスト | MIT |
| `happy-dom` | テスト時に画面の操作を再現（開発専用・配布物には含まれません） | MIT |

依存する `onnxruntime-web` のライセンスはMITです。配布物には `dist/licenses/` に実行用プログラムのライセンスを同梱しています。依存関係を変更して再配布する場合は、ライセンス表記も確認してください。fusejiのコードは使用していません。

## npmパッケージで配布する

画面・検出処理・ブラウザ内AIの実行プログラムをnpmパッケージにまとめられます。学習済みモデルとtokenizerは含めず、別途配置します。配布パッケージのインストール時に追加のnpm依存パッケージやモデルを取得する処理はありません。

`npm run package` で `packages/confidential-sanitizer-0.1.0.tgz` を作成できます。GitHub Actionsの「Build npm package」からもダウンロードできます。npmレジストリへの公開は行いません。詳しくは [npmパッケージの作成・利用方法](docs/npm-package.md) を参照してください。

## 画面の文言を編集する

**`src/content/ja.json`** に、ボタン名・説明・使い方・進捗・エラー・種別名・ダウンロード名を集約しています。JSONは「項目名と内容」を並べたテキスト形式です。たとえば `"button.check": "チェックを実行"` の右側を書き換えると、ボタン名を変更できます。

ソースを編集する場合は [画面文言の編集方法](https://github.com/smjr3/confidential-sanitizer/blob/main/docs/ui-text.md) を参照してください。配置は `src/ui/template.ts`、見た目は `src/ui/style.css`、処理は `src/main.ts` に分離しています。
