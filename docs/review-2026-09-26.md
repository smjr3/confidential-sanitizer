## 修正内容

| 問題 | 修正 |
| --- | --- |
| 法人番号の検査計算の重みが逆 | 国税庁の例 `8700110005901` に合わせて修正。旧実装が受理した `1700110005901` を不正として検査 |
| 再チェックで解除・種別・置換先の編集が消える | IDが同じ候補の編集状態を引き継ぐ。形式のみの再チェックでAI候補や手動候補を消さない |
| モデルの配置確認中に入力を消去・変更しても解析が始まる | 実行番号と入力の版番号を確認し、古い解析・進捗・エラーを無視 |
| AI起動失敗後に失敗したWorkerを再利用する | 失敗時にWorker（画面とは別の計算処理）を破棄。次回は再作成。正常完了時は再利用 |
| 置換先編集後に表全体を作り直し、続くクリックを失う可能性 | 同じ行の入力部品を保持して値を更新 |
| 自分で指定した置換先と自動番号が衝突する | 自分で指定した文字列を予約して、自動番号が重ならないようにする |
| NERのO（固有表現ではない）を組織として扱う | Oを除外。位置を照合できない単語や途切れた連番をまたいで連結しない |
| 候補が多いと重なり判定を何度も総当たりする | 区間の重なりを効率よく照合。表示・出力・内訳は同じ計算結果を使用 |
| コピー待ち中に入力が変わっても古い成功表示が出る | 表示の版番号が一致するときだけ通知 |
| CSPでWASM実行を許可していない | `script-src` にWASM専用の `'wasm-unsafe-eval'` を追加。同一配信元の制約を保持 |
| ローカル配信中のファイル読み出しエラーが未処理 | 読み出し失敗・ブラウザの切断時にストリームを終了 |

法人番号の根拠：[国税庁・チェックデジットの計算方法](https://www.houjin-bangou.nta.go.jp/documents/checkdigit.pdf)。
CSPの説明：[MDN script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)。

## 残る制約

- ルールとAIには誤検知・検知漏れがある。番号の検査に通っても実在する番号とは限らない。
- AIの単語位置は文字列照合による推定。長文の分割境界・未知語・表記揺れには引き続き注意が必要。
- URL末尾に日本語の説明文が空白なしで続く場合など、文字列の境界が曖昧な例は目視確認が必要。
- 独立した値同士に利用者が同じ置換先を明示指定することは可能。CSVを使って逆置換する際は内訳を確認する。
- 多数の異なる候補は表・ハイライトの描画量が増える。性能測定は計算部分に限る。
